How Steady fits together

A TypeScript full stack scaffolded with Better Fullstack: React in the browser, a Hono API, Postgres through Drizzle, and Better-Auth for sessions. The first diagram shows the layers. The second shows how screener, journal, and summary data move through them. The rest show every table and its columns, first all together, then milestone by milestone. This is the planned system from spec v0.1 and docs/prd.md; none of it is built yet.

What each piece is for

LayerChoiceWhy it fits this spec
FrontendReact + TanStack RouterTyped routes. Route loaders can ask the API for gate status before showing the diet screen, but the API still decides.
APIHonoSmall TypeScript server. The auth check and the screen gate are both middleware you attach per route.
ORMDrizzleTyped queries and SQL migrations. Screener tables can live in their own schema.
DatabasePostgresA real server-side store for syncing across devices. Most hosts encrypt it at rest.
AuthBetter-AuthUsers and sessions stay in your own Postgres, not with a third-party auth company.
PDF@react-pdf/rendererDefault from the PRD. Runs on the server from the reviewed snapshot, only when the user taps Export.
RuntimeNode + npmAlready installed. Bun was the first idea, but Node removes the question of whether the PDF library runs under Bun.
